OctoCheck

Code review that runs inside Claude Code, one step you approve at a time. It reads your code, flags problems with file and line number, and never edits anything.

Before you start

You need three things on your machine, then one command inside the project you want reviewed.

What you need

  • Claude Code, signed in
  • Git, with your project already a Git repository
  • Node.js 16 or newer, only for the install command

It reviews Python, Java, HTML, CSS, JavaScript and Frappe code.

Install

Open a terminal in your project folder, and run:

npx github:Octo-Advisory/octocheck .

The dot means "this folder". To install somewhere else, put that folder's path instead.

Turn on the safety hook

This is what guarantees OctoCheck cannot edit your code. Add the block below to your project's .claude/settings.json. If the file already has a "hooks" section, add the entry inside it rather than replacing the file.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit|NotebookEdit",
        "hooks": [
          { "type": "command", "command": "node .claude/hooks/block-source-write.cjs" }
        ]
      }
    ]
  }
}

Without the hook, OctoCheck is still told not to edit your code, but nothing stops a mistake. With it, any write outside the octocheck/ folder is blocked.

      Check progress and results
      
      
      Everything is stored as plain files in the octocheck/ folder, so you can check in any time, even after closing VS Code.
      
      
      
        
      In the chat
      After every task, Claude Code tells you where things stand and waits.
      Task 3 of 14 complete — 4 flags found.
Continue with Task 4? (yes/no)
      
        
      progress.json
      Every task is marked pending or done. This is also how a review resumes later.
      { "id": 3, "name": "app/parsers",
  "status": "done" }
      
        
      plan.md
      The plan you approved. Read it to see which tasks exist and what each one covers. Contract and flow tasks are added during the run and show up in progress.json.
      
        
      reports folder
      One report per run, named with the date and time, so runs never mix. It grows after every task, so you can read findings while the review is still going.
      octocheck/reports/
  report-2026-10-05-101530.md
      
      
      
      
      
        
      
          
      Close VS Code halfway?
      
          
      Nothing is lost. Open Claude Code in the same project and run /octocheck-continue. It carries on at the next pending task.
      
        
      
        
      
          
      Run it again after fixing things
      
          
      Run /octocheck-init again. You get a new report. Files you did not touch are skipped, and their earlier flags appear under "Not re-reviewed this run", so an old problem never disappears just because nobody looked at it again.
      
        
      
      
      
    
      
  
      

  
      
    
      
      
      Options and settings
      
      
      The defaults work for most projects. These are the ways to change them.
      
      
      
        
      Commands
      
        
      
          
      CommandWhat it does
      
          
            
      /octocheck-initBuilds the plan and waits for your approval.
      
            
      /octocheck-init mainPlans a review of only the files that differ from the main branch. Fastest way to review a feature branch.
      
            
      /octocheck-continueRuns one task, then asks before the next.
      
            
      /octocheck-continue --autoRuns the remaining tasks without stopping after each one. It applies to that run only, and it still stops on a high-severity flag, a blocked action, or a change that affects too many files.
      
                
        
      
      
      
      
      
        
      
          
      Settings file
      
          
      The installer creates octocheck.config.yaml in your project. Use 0 or off to switch a setting off.
      
          
      # Re-review a file not checked in this many days,
# even if it has not changed.
review_expiry_days: 19

# Ask first if one change would pull in more
# than this many other files.
blast_radius_limit: 25
      
        
      
        
      
          
      Critical flows
      
          
      Tell OctoCheck which paths matter most, and it traces them end to end whenever a file on them changes. Add this to your CLAUDE.md, or let /octocheck-init ask you for it.
      
          
      ## Critical flows
- checkout: app/cart.py → app/pricing.py → app/pay.py
      
        
      
      
      
      
      
        
      Update to the latest version
      
        
      Run the line for your terminal from your project folder. Your rules, settings and past reports are left alone.
      
        
      macOS, Linux, WSL

      Questions
      
      
       
      
      
      Will it change my code?
      No. It reads your code and writes only inside the octocheck/ folder. With the safety hook turned on, any attempt to edit a file elsewhere is blocked.
      
      
      Does it run by itself?
      Not yet. You start each run. A scheduled run that needs nobody at the keyboard has not been built.
      
      
      How much Claude usage does a review take?
      It uses your Claude Code usage like any other session, and it grows with the number of files reviewed. Skipping unchanged files and using /octocheck-init main keep repeat runs small.
      
      
      A flag is wrong for my project. What now?
      If a rule doesn't fit how your team works, turn it off in rules.local.yaml using the builder above. If a rule is wrong in general, open an issue on GitHub with the file, the line, and the rule ID.
      
      
      Why did it re-check a file I didn't touch?
      Because something that file uses changed. The report says which file changed and why. It also re-checks a file whose last review is older than the expiry setting.
      
      
      What can it not catch?
      It reads code but never runs it, so bugs that only appear while the program is running are out of reach. Connections built from text at runtime can also be missed. Tests remain the backup for those.
